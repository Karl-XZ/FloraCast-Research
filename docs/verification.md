# 验证方法与记录

## 1. 安装与运行

从仓库根目录执行：

```bash
npm ci --prefix server
npm test --prefix server
npm run verify:local --prefix server
```

`npm test` 运行已有的 `server/tests/*.test.js`，以及此次为历史气象来源和缺失值修复新增的回归用例。外部数据请求由测试中的固定输入或替身覆盖。

`verify:local` 在空闲端口启动独立 Node 服务，检查根路径、`/FloraCast/` 子路径、两种健康检查地址、核心前端脚本和研究页面，共 7 项；完成后停止该进程。该命令不请求远端 AI，也不验证浏览器中的三维渲染。

## 2. 自动化覆盖

| 文件 | 检查内容 |
|---|---|
| `connectors.test.js` | 年份范围、连接器输入与气象缺失值、积温跨年重置 |
| `forecast.test.js` | 预测特征不使用目标时段数据；递推保持合成时间间隔 |
| `ground-validation.test.js` | 地面观测日期和方法对照、缺少可比较估计的处理 |
| `literature.test.js` | 文献元数据、固定样例和服务异常处理 |
| `modis-quality.test.js` | 数值缩放、缺失值、云雪质量标记和空间样本聚合 |
| `phenology.test.js` | 季节曲线拟合、分年方法、稀疏输入与数据质量 |
| `research.test.js` | 任务队列、取消、暂停恢复、快照复算和校验值 |
| `weather-data.test.js` | 来源不可用时返回错误、旧缓存不直接复用、降水缺失值保留 |

GitHub 工作流 [verify.yml](../.github/workflows/verify.yml) 使用相同的安装与验证命令；在 Gitee 下载的代码也可以本地执行。

## 4. 结果解释

- 物种识别分数用于候选排序，物种结论结合形态与独立观察确认。
- iNaturalist 观测数量受观察者活动与上传覆盖影响，不能直接当作植物种群数量。
- 历史事件匹配分数表示实现条件下的相似程度；科学结论需说明基线、变量权重和筛选阈值。
- 卫星合成、天气逐日值、照片观测和 AI 上下文分别保留实际日期。
- 单元测试、服务检查、远端接口验证和独立地面验证各自记录，报告时写明覆盖范围。

## 5. 可选现有检查

`server/tests/live-science-smoke.js` 会请求真实科学数据，结果写入 `test-results/`；需要网络，运行前阅读其中固定地点与年份。`server/tests/jiuwen-smoke.js` 需要 Python/openJiuwen 环境。`browser_smoke.py` 需要 Playwright 及浏览器，原脚本以 `localhost:5179` 为地址，运行时须使用相同端口。
